# Web 创作中心设计

## 目标与边界

让多个创作者各自登录、建立并维护自己的互动故事；每部故事的草稿可逐项自动保存、校验、发布和下架。创作者只操作自己的项目，不提供同一剧本多人共编。游玩端仍只读取已发布版本，不接触草稿、隐藏规则或作者凭据。

项目继续采用单仓库，但把浏览器应用、服务端应用、共享类型、规则引擎和剧本装配明确分层。创作中心不继续堆在现有 `App.tsx` 和 `app.ts` 中。

## 工程结构

- `apps/web/src/play/`：现有游玩界面及其状态逻辑。
- `apps/web/src/creator/`：账号入口、项目列表、配置编辑页、校验与发布状态。
- `apps/web/src/shared/`：只包含前端通用 HTTP 客户端与界面基础组件。
- `apps/api/src/play/`：游客存档和游玩接口。
- `apps/api/src/creator/`：账号、草稿、校验、发布和权限接口；路由不依赖前端代码。
- `packages/contracts/`：两端共享的公开请求与响应类型，以及剧本定义。
- `packages/script/`：磁盘样例和草稿 JSON 的统一装配、归一化与校验。
- `packages/engine/`：纯游戏规则，不依赖 Express、SQLite 或 React。

根目录采用 npm workspaces，前后端各有独立 `package.json` 和开发／构建入口。共享包用包名导入，禁止跨应用相对路径导入源码。保留根目录组合命令，现有单机开发启动方式继续有效。

## 作者身份与数据

创作者账号采用用户名和密码。密码用带随机盐的 scrypt 哈希保存；登录成功后使用 HttpOnly、SameSite Cookie 和服务端会话。写接口校验请求来源。作者身份和游客游玩身份分离。所有项目查询、修改、删除、发布都由服务端按作者 ID 过滤。

SQLite 中保存账号、会话、项目、草稿配置项和已发布剧本。项目有全局唯一、不可变的故事 ID 和所有者；每个配置项保存 JSON 内容、修订号和修改时间。草稿允许暂时不满足完整剧本校验；发布时必须一次性通过 JSON 解析、字段校验和跨文件引用检查。发布记录保存不可变的规范化剧本 JSON、版本和内容哈希；目录展示项目当前发布的记录。

删除项目采用下架和软删除：立即从创作列表与故事目录隐藏，不自动清理已有玩家存档或历史发布记录。第一版不提供恢复入口，因此删除前需要明确确认。

## 编辑流程

进入创作中心后可新建空白故事，或复制内置示例到自己的新项目。故事配置按 `manifest`、玩家表单、玩家指标、玩家规则、地点、道具、结局、成就切换标签。角色区是可新增／删除的 NPC 列表，选中角色后切换基础信息、指标、人格、规则、世界资料标签。

常用字段使用可读标签与表单控件；数组可新增、复制和移除，复杂条件与效果提供结构化编辑入口及 JSON 高级编辑。每个标签保留本地草稿，切换标签或短暂空闲后自动保存。保存请求带配置项修订号；旧标签页不能覆盖另一标签页较新的内容，冲突时显示重新载入与保留本地内容的选择。保存失败时本地内容和错误提示保留，不显示“已保存”。

右侧显示当前标签的帮助与校验问题。发布按钮先保存当前标签，再由服务端验证整部剧本；错误定位到具体文件和字段。发布成功后展示版本、时间和目录入口。修改已发布故事继续写草稿；再次发布会更新目录指向的版本。游玩存档继续用版本和内容哈希检查兼容性，已发布内容更新可能使旧存档不能继续，新版本发布前需展示提醒。

## 运行时边界

游玩接口通过剧本仓库读取内置示例及当前已发布项目。草稿不可进入目录。现有 `loadScript`、`listScripts` 的磁盘接口仍可用于测试和内置示例；API 由依赖注入的仓库提供统一 `get/list`。发布后读取数据库中的规范化快照，不在运行时从多个可变草稿文件拼装。

## 界面语言

沿用现有米白背景、深蓝正文、赭色动作色、宋体标题和 DM Sans 英文辅助字。创作区是高密度的工作台：固定顶栏、左侧故事／配置导航、中部表单、右侧帮助与错误；窄屏收起辅助栏。所有保存、冲突、校验、发布和空状态都有明确反馈。

## 验收

- 两个作者账号只能看到和修改各自项目；未登录不能调用创作写接口。
- 新建、编辑、刷新和跨标签切换后草稿不丢失；并发旧修订不能覆盖新内容。
- 新建和复制示例均能组成可发布剧本；错误引用阻止发布并给出定位。
- 发布后的故事出现在游戏目录，可以开新游戏；草稿与下架故事不出现。
- 删除只下架项目，不抹除玩家存档。
- 原有游玩接口与测试继续运行；前后端构建各自通过，关键编辑流程在浏览器验证。
