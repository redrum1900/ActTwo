# 创作者草稿试玩设计

日期：2026-10-03

## 目标与边界

创作者从故事编辑页随时为**已保存的当前草稿**创建一次独立试玩。每次点击“开始试玩”都生成新的 UUID 试玩 ID 和不可变的草稿快照，从新游戏开始；“继续试玩”只读取该试玩 ID 的快照和自动存档。草稿后续修改、正式审核发布及其他试玩均不改变旧试玩。试玩对话使用现有 AI 适配器，产生正常的模型调用与费用。

本功能不修改正式故事的已发布快照、玩家自动／手动存档、故事目录或审核流程。统一账号、AI 调用记录与“智能导入只调用 AI 一次”的简化分别设计；试玩依赖统一账号，并接入调用记录。

## 方案选择

选择一条创作者试玩记录作为完整的持久化单元：同一条记录内保存冻结剧本快照和这次试玩的自动存档。复用现有游戏引擎及 AI 对话逻辑，但请求必须走创作者认证和试玩 ID 定位，不借用公开 `/api/games/:gameId` 的正式剧本仓库或访客存档。

不采用“每次打开重新读取实时草稿”，因为它会让旧试玩的规则和进度不匹配；也不把试玩塞入正式游戏手动存档槽位，因为当前槽位只有 0–5，且会污染正式玩家的版本与存档语义。

## 数据与不变量

- MySQL 中使用一张 `creator_playtests` 表；每行就是一次试玩，包含 `id`、`project_id`、`owner_id`、`script_json`、`script_hash`、可空的 `auto_state_json`、`auto_revision`、创建时间和最近游玩时间。快照一经创建不可编辑；开局尚未完成时自动存档为空。不另建试玩存档表，也不写入正式 `save_slots`。
- 试玩记录仅归故事所属创作者可见；所有读取、动作、对话和删除都同时校验统一登录账号、故事归属与试玩 ID。新标签复用统一账号会话，不依赖访客 Cookie。
- 同一故事最多 10 条试玩记录。创建第 11 条时，在同一数据库事务中按创建时间、ID 稳定排序，删除最老的一行；该行的快照与自动存档随之一起删除。手动删除也是删除对应一行，不可恢复。若被删除的试玩页仍开着，后续请求返回“试玩记录已删除”，不回退到当前草稿。
- 每个试玩只有自动存档，不提供正式游戏的手动存档槽、导入／导出存档功能。自动存档更新使用修订号避免并发覆盖；AI 对话沿用 turn ID 去重，重试不能重复结算或重复保存。
- 试玩 ID 与正式故事 ID、发布版本号是不同概念。展示草稿快照创建时间和试玩 ID；正式发布版本不会覆盖试玩快照。

## 创建与游玩流程

1. 编辑页顶部“试玩”按钮打开右侧抽屉，顶部“开始试玩”，下方按创建时间倒序显示最多 10 条记录；每条显示创建时间、最近游玩时间、简短试玩 ID、是否已有自动存档，并提供“继续试玩”“删除”。界面沿用创作中心已有的暖纸色、深色文字、赭色强调与细边框，不引入另一套视觉系统。
2. 页面有未保存修改时，不直接创建试玩；提示先保存。点击开始后，服务端从数据库读取当前已保存草稿，执行现有**确定性运行校验**，不调用 AI。草稿不能运行时返回具体配置路径与错误，不创建试玩记录，也不覆盖任何旧记录。校验只用于试玩启动，不改变作者保存不完整草稿的权利。
3. 校验通过后，在事务中冻结剧本、创建试玩 ID 并执行 10 条上限清理。前端用新标签打开专用创作者试玩地址；旧编辑页与抽屉保持打开。
4. 新试玩页沿用现有游戏 UI。若剧本有开局资料，先填写开局资料；提交时依据冻结快照初始化游戏状态，并写入该试玩记录的 `auto_state_json` 与修订号。若无需填写，直接在同一行初始化存档并进入游戏。创建记录成功但尚未提交开局资料时，列表显示“未开始”，仍可从该记录继续完成开局。
5. 继续试玩只打开对应试玩 ID 的新标签：该行有自动存档则读取进度，没有则进入该快照的开局资料页。地点行动、搜索、取物、规则结算和聊天均依据冻结快照执行；成功结算后只更新同一行的自动存档与修订号。
6. AI 对话调用现有主游戏的对话适配器，并按每次实际模型请求写入统一调用记录，标记 `playtest`、登录账号、故事与试玩 ID；不伪造免费回复，也不因编辑器打开而调用 AI。失败时保留原有存档与修订号，允许玩家重试。

## 接口与实现边界

- 创作者接口提供列出、创建、读取、删除试玩记录，以及单个试玩的开局、当前状态、行动和流式聊天。所有接口位于 `/api/creator` 下，以统一账号会话校验所有权。
- 存储层将试玩快照和自动存档作为同一行聚合管理，创建、初始化及后续存档更新都按试玩 ID 定位；不拆成两张表，也不复用 `save_slots` 表中的正式玩家数据。游戏层抽取或复用现有状态初始化、动作结算、视图构建与 AI 聊天逻辑，避免实现第二套规则引擎。
- 前端专用试玩路由复用现有游戏视图和交互组件，但隐藏正式游戏目录、手动存档与发布版本入口；后端请求始终带试玩 ID。创作者抽屉只管理试玩列表，不在抽屉里运行游戏。
- 试玩记录中的封面、道具图片等资产若引用草稿资产，读取时仍按创作者权限访问；记录删除时按现有资产引用策略处理，不误删被草稿或其他试玩引用的文件。

## 验证与异常

- 覆盖：每次开始都生成不同 ID；每条记录的快照和自动存档位于同一行，未开始时存档为空；两次试玩互不影响；修改草稿后旧试玩保持旧快照、新试玩使用新草稿；自动存档继续；AI 对话确实调用适配器并按原有失败语义保留进度。
- 覆盖：无权访问返回拒绝；第 11 条清理最老记录；手动删除与打开中的旧标签；同时创建时仍保持最多 10 条；存档修订冲突不丢数据。
- 覆盖：未保存修改提示、草稿无效不创建记录、开局资料未提交可恢复、页面刷新和重新打开新标签、服务器重启后仍能继续。
- 试玩只是创作者验证工具，能试玩不等于通过剧情审查；试玩本身不使用 AI 审查或自动修改草稿。
