# 剧本、玩家与 NPC 运行时状态设计

> 后续决策（2026-10-01）：地点访问配置与地点定义合并。下文提到的剧本级 `placements.json` 和 `GameScript.placements`，最终都由 `locations.json` 各地点上的 `visibleWhen`、`enterWhen` 取代；NPC 位置仍由 `base.initialLocationId` 与存档 `npcLocations` 管理。

日期：2026-10-01

## 目标与边界

同一套规则引擎继续支撑可配置、多 NPC 的对话游戏，同时让《屏幕那端的剑道女生》成为新机制的完整样本。玩家状态可以由探索等自身行为改变，也可影响之后与 NPC 的对话；规则效果可明确指定修改玩家或任意 NPC。剧本 JSON 只定义初始资料与规则，游玩不改写它们。存档保存事实；剧本、玩家、NPC 的运行时快照是按当前事实计算的查询结果。

本次包含配置格式、加载与校验、存档状态、地点门禁、规则结算、AI 上下文、游戏日志、页面视图及测试。删除 `content/mystery-town/`，清除其相关测试与旧规则分支；现有存档不迁移。暂不做账号、创作者 UI、MySQL、远程剧本发布或其他新故事。

## 配置结构

### 地点与 NPC 所在地

`locations.json` 保留地点 ID、名称、描述、地点物品、调查点，增加 `interactionMode: "online" | "in-person"` 供页面和 AI 描述交互方式。苏念剧本的初始地点改为独立的「电脑上」，不再用「玩家家中」表示远程聊天。地点不负责推算 NPC 所在地。

新增剧本根目录的 `placements.json`，每个地点必须恰有一条访问配置：`locationId`、可选 `visibleWhen`、可选 `enterWhen`。`visibleWhen` 首次满足时将地点加入存档的 `unlockedLocations`，之后保持可见；未配置 `visibleWhen` 表示开局可见。`enterWhen` 每次生成视图和执行移动时根据最新存档检查；未配置即允许进入。起始地点必须在初始状态下可见且可进入。地点可见但暂时不可进入时，玩家若已在该地点，不被强制传送；离开后才受重新进入限制。前端只使用后端返回的 `enterable` 禁用按钮；后端收到移动请求时再次调用同一门禁函数。

NPC `base.json` 增加 `initialLocationId`，移除 NPC 专属 `placements.json` 和旧的固定 `locations`。存档中的 `npcLocations[npcId]` 是 NPC 当前地点的唯一事实。`moveNpc` 规则效果改变它，目标地点无须已对玩家解锁；角色快照由该值显示所在地。苏念开局在「电脑上」，见面和去她家时由相应规则显式移动。NPC 从当前地点离开后不再出现在该地点列表；当前聊天显示本轮已结算的最后回复，然后提示离开并返回地点页。

### 玩家配置与通用条件／效果

`player-form.json` 只定义新游戏时填写的资料。可选的 `player/indicators.json` 与 NPC 指标使用相同类型：`number`、`boolean`、`enum`、`tags`、`text`，包括初始值、范围／选项及 `playerVisible`。不配置即为空。表单资料不会自动复制成指标；玩家规则可读取资料，只有需随游玩变化的值才定义为指标。

可选的 `player/rules.json` 使用与 NPC 规则一致的条件、优先级、`once` 和效果格式，但只支持 `automatic` 与明确的 `action` 触发，不参与 AI 语义候选。动作规则可选配置 `actions`，值限定为 `move`、`wait`、`explore`、`search`、`take`、`chat`；不写则适用于所有有效操作。地点调查点的直接效果仍写在 `locations.json`。

条件系统增加 `playerIndicator`、只读的 `playerField`（对表单值做等于或数组包含比较）；保留带明确 `npcId` 的跨 NPC `indicator`，并增加 `npcLocation` 用于检查 NPC 当前位置。`all`、`any`、`not` 继续组合这些条件及地点、时间、道具条件。对指标类效果增加可选 `target: "player" | "npc:<id>"`：在 NPC 规则中省略时默认为该 NPC，在玩家规则中省略时默认为玩家。规则归属决定触发来源，`target` 决定被修改对象。`moveNpc` 使用同样的目标格式，但目标必须为 NPC；NPC 自身规则可省略目标。道具仍由全局 `itemStates` 记录唯一归属，不能在玩家和 NPC 快照中各存一份。

加载器对地点、指标、道具、NPC 名称／ID 引用做归一化与类型校验。剧本上传或加载时对未知目标给出带 JSON 路径的诊断警告；运行时找不到目标只跳过该效果，并记录诊断，其他有效目标效果继续执行。除未知目标之外，非法类型或破坏道具唯一归属的效果使该规则本次整体失败，不提交其已暂算的效果。`once` 规则只有至少一个效果造成实际状态变化时才记为完成；部分效果成功也算完成，跳过的效果列入诊断。

## 存档与运行时快照

存档保存 `scriptId`、版本及内容指纹、玩家资料和当前位置／时间、`playerIndicators`、`npcIndicators`、`npcLocations`、道具归属与标签、剧情标记、已发现地点／NPC／物品、一次性规则记录、聊天、压缩记忆和活动日志。原始 JSON 不复制到存档；`playerItems`／`npcItems` 等旧兼容投影及旧阶段状态不再作为新结构的数据来源。新建存档按剧本初始值生成。现有存档直接作废，不提供迁移。

读取或提交存档后按需计算：

- 剧本快照：已发现地点及 `enterable`、当前场景可见的 NPC／调查点／物品、结局与成就的当前展示状态。
- 玩家快照：资料、位置／时间、指标当前值和可见性、由道具归属计算的背包。
- NPC 快照：当前地点、通用人格与命中条件人格、指标当前值和可见性、由道具归属计算的背包。

快照不独立持久化；API 存档修订号用于客户端防旧请求，后续如需性能优化可按修订号缓存。后端内部快照可包含判定所需信息；发给浏览器的投影过滤隐藏地点、隐藏道具、隐藏指标与未获得的隐藏图鉴信息。剧本定义的 `endings.json`、`achievements.json` 不改写；当前条件可满足与已经永久获得是两个字段。获得记录仍跨存档保存在图鉴表，不因读档撤销。图鉴授予移到操作结算及持久化流程，GET 查询不写图鉴。

新存档绑定规范化剧本的内容指纹；即便作者忘记提升版本，同版本 JSON 改动也不能悄悄作用于旧存档。发布版应提升版本并新建存档；未来的平台发布管理另行设计。

## 一次操作的结算顺序

1. 服务端按当前存档校验动作；移动动作同时要求地点已发现、当前 `enterWhen` 为真。对话只允许当前地点可互动的 NPC。
2. 执行动作直接效果，或由 AI 对当前 NPC 的语义规则提出 ID、后端复核后执行。AI 不直接写状态。
3. 以直接效果之后的同一状态，预先收集本轮满足条件的玩家与 NPC 自动规则。固定按优先级及稳定 ID 顺序执行一次；自动规则产生的新条件不在本轮继续连锁触发。`exclusiveGroup` 在同一规则归属者内部互斥，避免不同 NPC 恰好使用相同组名而互相排斥。
4. 刷新永久地点发现、NPC 可见性、图鉴条件；计算前后差异、活动日志、角色离场提示。玩家隐藏指标变化不直接出现在公开日志，规则可提供不泄密的叙述。
5. 将自动档、图鉴获得记录和修订号作为同一次持久化提交，再生成公开快照。失败不留下半次操作；聊天 `turnId` 保持幂等重试。

NPC 原有语义链路保持：只向 AI 提供正在对话的 NPC 的候选规则；后端复核条件；必要时按最终结算结果修订角色回复。玩家规则不加入候选列表。若语义规则或自动规则移动 NPC，本轮最后回复仍需与离场事实一致，然后聊天关闭。

## AI 知情边界

AI 输入由世界背景、当前地点／时间、玩家相关公开资料、当前 NPC 的命中人格、该 NPC 自己的指标与可知道具、压缩后的对话记忆及当前候选规则组成。玩家隐藏指标不整包发送。作者可以通过玩家规则或其他规则的 `target` 效果修改某个 NPC 的知情指标；`personas.json` 或 `lore.json` 根据该指标和玩家当前状态提供该 NPC 此刻知道的描述。语义候选的 `candidateWhen` 同样必须包含知情门槛，防止候选事件文字泄露未知事实。后端仍用完整存档检查真正的生效条件。NPC 不会因为玩家状态改变而自动得知远处发生的事。
