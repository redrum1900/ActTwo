# 剧本指标、类型化条件与规则结算设计

## 目标与范围

作者用同一套规则表达「什么时候触发」与「触发后改变什么」。剧本指标与玩家、NPC 指标并列；三者均支持数字、是非、选项、文本、标签数组及日期，并在条件编辑器中按类型提供相同的比较能力。开局资料是玩家开局填写的静态值，也可作为条件。地点道具、结局、成就、玩家规则和 NPC 规则复用同一个条件编辑器；玩家／NPC 规则另有结算效果编辑器。既有地点道具与道具标签移除改动保留并一起回归测试。

## 配置与作者界面

### 剧本指标

- 用 `story/indicators.json` 定义剧本级指标；创作中心将旧「属性定义」页替换为「剧本指标」。每项新建时生成 UUID，表单不暴露可编辑 ID。
- 指标字段为名称、描述（多行文本）、类型、默认值。数字类型另有最小／最大值，选项类型另有选项列表；默认值随类型切换为相应控件并校验类型与范围。剧本指标默认只供规则使用，不自动展示给玩家或注入 AI 提示词。
- 玩家、NPC 指标沿用现有定义，同时增加日期类型；三类指标采用同一类型和值校验。已存在的指标 ID 保持不变，新建时自动生成 UUID，引用不随名称修改而改变。
- 新故事不再创建旧 `stats.json` 属性。旧已发布版本按原格式继续运行；旧作者草稿里的非空 `stats.json` 不自动丢弃，发布前提供可定位的迁移错误，并提供将 `world/player/npc` 数值属性分别迁到剧本／玩家／NPC 数字指标的操作。迁移遇到 ID 冲突时停止并要求作者处理，不覆盖现有指标。旧存档不做跨格式迁移。

### 开局资料

- `player-form.json` 允许空数组；为空时跳过开局问卷。每项可新增、删除、排序，新增项自动生成 UUID，已有 ID 保持不变。
- 表单主要字段为标题、类型和默认值；类型含单行文本、长文本、日期、Select、Radio、Checkbox。后三种提供选项编辑；默认值必须属于已配置选项，Checkbox 默认值为数组。
- `required`、`editable`、`public` 现有语义保留，收进紧凑的高级设置，不在每张卡片铺满大输入框。删除被条件引用的资料时提示引用，保存／发布校验仍拦截悬空引用。

## 类型化条件

三个指标来源（剧本、玩家、NPC）共用比较组件，开局资料依其字段类型使用同一运算符规则：

| 值类型 | 运算符 |
| --- | --- |
| 数字 | `=`、`≠`、`>`、`≥`、`<`、`≤` |
| 单行／长文本 | 等于、不等于、字面包含、字面不包含 |
| 标签数组／Checkbox | 包含、不包含指定成员；数组长度 `=`、`>`、`≥`、`<`、`≤` |
| 日期 | `=`、`≠`、`>`、`≥`、`<`、`≤` |
| Select／Radio | 等于、不等于 |
| 是非 | 是、否 |

数字严格区分 `>` 与 `≥`、`<` 与 `≤`。文本比较是区分大小写的字面比较，不交给 AI 解释。日期为经过真实日历校验的 `YYYY-MM-DD`，按日比较，不受时区影响。数组长度是非负整数；未填写或类型不匹配的值不会意外满足条件。AND、OR、NOT 分组及事件、物品、地点等非指标条件保留。类型切换时重建合法比较值，不静默保留不相容参数。条件配置的引用、类型、运算符和值都在发布前校验。

`completedEvent` 不再出现在作者条件中；剧情事实使用按 UUID 匹配的 `storyEvent`，规则执行记录由一次性机制负责。旧格式条件在旧已发布版本中仍可运行，新草稿若使用已废弃的作者条件则给出迁移提示。

## 玩家与 NPC 规则结算

规则编辑器明确分成触发方式／触发条件／结算效果。NPC 语义判断与玩家动作、自动规则仍按现有候选和服务端复核流程运行；AI 不直接改变状态。满足条件后，效果在临时状态中原子结算，失败时不写入任何部分结果或一次性记录。

作者可配置的结算效果包括：

- 按已定义 UUID 记录或移除剧情事件；移除只清除快照当前有效标记，不删除事件定义或历史活动记录。
- 给予、移除或转移道具，继续遵守唯一归属；无效持有者或物品使该次结算失败。
- 对剧本、玩家、指定 NPC 指标设置合法值；数字指标可增减，标签数组可添加／移除成员；其他类型用设置值。数值变化受上下界限制。

结算 UI 用选择器展示名称、保存稳定 ID；指标类型决定值控件。规则顺序、优先级、互斥组、`candidateWhen` 与同轮自动规则时机沿用现有语义。成功结算后刷新条件人格、地点、物品、图鉴和玩家视图，并保留存档修订冲突保护。

### 一次性规则

一个剧本级标签数组指标作为系统管理的「已执行规则」集合，元素为**规则 ID**而不是剧情事件 ID。新故事创建时生成并保存它的 UUID；旧草稿在首次明确保存新格式时补建并持久化，装配时绝不临时生成随机 ID。该指标在指标页只读展示，不允许改类型或删除。创作界面保留简单的「仅触发一次」开关；启用时，服务端在触发前检查集合中没有该规则 ID，在其他效果确实成功后与效果一起原子写入规则 ID。重复触发不再次加分。移除剧情事件不会重置一次性记录；第一版不提供重置一次性记录的作者操作。该集合不自动写玩家日志，也不作为剧情事件展示。规则 ID 必须在剧本内唯一。

旧 `completedEvents` 仅用于旧已发布剧本／旧格式存档的运行兼容，不再作为新作者条件或新规则的一次性真相源。旧存档不自动转换；发布内容指纹变化时继续使用现有不兼容处理。

## 验收

- 三类指标每种类型的初始值、读写、六类对应条件及错误配置均有单测；日期、数组长度、严格不等号边界有专项测试。
- 开局资料可删至零项；选项、默认值、条件引用和紧凑页面的新增／删除／保存／重置流程可用。
- 同一条件树可用于图鉴、地点道具及规则；无效引用不能发布。
- NPC／玩家规则混合效果原子结算，事件和道具归属正确进入快照；结算失败不产生一次性记录。
- 多个加分规则各只执行一次，不要求定义多个剧情事件；删除某剧情事件不让加分规则重复执行。
- 原有苏念剧本、地点道具及道具标签移除行为不回归；全量测试和构建通过。
