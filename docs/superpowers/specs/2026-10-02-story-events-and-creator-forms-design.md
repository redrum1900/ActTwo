# 剧情事件与道具、图鉴创作表单

日期：2026-10-02

## 目标与已确认边界

让作者不用手写 JSON 就能编辑道具、结局、成就及其复杂条件；把目前含糊的“规则执行事件”和自由文本 `flag` 合并为一种作者显式定义的“剧情事件”。玩家行动后仍由后端严格判断和结算，AI 只提出语义规则，不直接改快照。保留每个配置页的显式保存、重置、JSON 模式及现有创作中心视觉体系；跨配置引用使用已保存版本，未保存的新目标不进入下拉选项。表单不得删除未显示的合法字段。

本规格默认剧情事件 `label/detail` 仅供创作页选取、解释和存档记录；记录成功时**不自动向玩家展示**，玩家可见叙述仍由规则 `narration` 等现有途径控制。事件一经记录不可撤销，同一事件 ID 在一个存档中最多出现一次。若将来需要可撤销状态，应使用玩家或 NPC 指标，而不是剧情事件。

## 决策与替代方案

选用“在故事设定定义剧情事件 + 规则显式记录 + 快照按 ID 查询”的方案。继续使用无定义的字符串 `flag` 虽改动少，但作者无法获得名称、详情、合法选项与可靠的引用校验；直接把规则的 `completedEvents` 当剧情事实虽然无需写入效果，但一次性规则的内部执行记录与剧情语义混杂，作者也难以判断其成立时机。两者都不作为新的作者界面选项。

## 固定剧本与运行时数据

`manifest.json` 新增 `storyEvents` 数组，放在“故事设定”页的“剧情事件”区域，不新增独立配置文件。每项 `{ id, label, detail }`：`id` 由新建操作用 UUID 生成，保存后永不随改名、排序改变；`label` 为作者界面的名称，`detail` 为多行说明。已有事件 ID 不强制改成 UUID，但新建的必须是 UUID。删除事件必须检查当前已保存草稿中的所有引用，发布校验仍是最终权威；不自动重定向到其他事件。

组装后的 `GameScript.storyEvents` 与当前 `GameScript.events` 分开：后者仍是 NPC 互动规则，不改其含义。`GameState.storyEventFlags` 为剧本级快照事实，结构为 `{ id, label, detail }[]`。新游戏初始化为空；首次记录时，后端从已发布的 `storyEvents` 定义复制完整对象加入快照；判断只比较 `id`。存档绑定剧本内容指纹，事件定义随发布版本冻结，运行中不从作者草稿覆盖旧存档的副本。

新规则效果为 `{ "type": "recordStoryEvent", "eventId": "<uuid>" }`；新条件叶节点为 `{ "storyEvent": "<uuid>" }`。任意 `all`、`any`、`not` 组合都可包含它。后端验证目标 ID 存在且唯一，重复记录为无状态变化，不产生第二条快照记录。若某规则同时有其他有效效果，则仍按既有规则结算；任何非法效果使该规则整体失败，不会只留下剧情事件。规则先结算，随后在同一新状态上运行既有自动规则、地点刷新与结局/成就检查。自动规则的候选收集仍沿用现有“本轮预先收集、不递归连锁”的语义；不能因新事件在同一轮产生无限连锁。最终状态与图鉴按现有事务和修订号一起提交；AI 输出失败、请求失败或修订冲突时不单独写入剧情事件。

`completedEvents` 继续作为系统内部“规则已执行”记录，用于 `once`、候选筛选和诊断，不出现在普通条件编辑器。“剧情事件”只在规则明确使用 `recordStoryEvent` 时产生，不能因为某条规则被 AI 提议或仅满足前置条件就产生。玩家对话、探索、移动、等待、搜索与取物，只要实际执行了带此效果的有效规则，都走同一结算函数。剧情事件自身不自动写玩家活动日志，也不自动注入 AI 提示词；相关叙述和角色知情由规则与指标/性格条件显式配置。

## 创作页面

故事设定的剧情事件区域提供新增、选中、编辑名称和详情、删除；不展示可编辑 ID。规则表单中的“记录剧情事件”效果，以及规则/结局/成就的“剧情事件已发生”条件，都从已保存的 `storyEvents` 中通过 Ant Design `Select` 选择，展示 `label`、持久化 `id`。已保存目标被删除后，表单保留无效 ID 并就近显示错误，不默默清空。`NOT` 作用于事件条件时即“事件未发生”。

道具、结局、成就三个页面均采用地点页式内层 tab，一项一个 tab；“新增”创建唯一且稳定的隐藏 ID，现有 ID 原样保留；不提供“添加字段”。各项删除需确认。道具 `description`、`detail` 使用 textarea；`initialTags` 用可新增、删除的标签组件，不提供单独编辑或排序；`hiddenTags`、`variants` 等已有复杂字段在表单未实现前保留，JSON 模式仍可编辑。道具增加可选 `image`，显示项目图片上传、预览与移除；玩家背包/道具详情有图片时显示图片，无图时维持现状。结局和成就的 `description` 为 textarea；`hidden` 维持现有语义。

结局和成就共用递归条件编辑器，根分组及任何子分组可独立选择 AND（`all`）或 OR（`any`）；任意叶节点或分组可取反（`not`）。支持新增、删除、上/下移动、折叠，输入布局采用已确认的紧凑单行样式。条件类型按现有 `Condition` 联合类型提供对应控件，选择 NPC、玩家指标、地点、道具、规则等引用时使用 Ant Design `Select`，而不是要求作者输入 ID；选择“道具”后紧接道具列表，再选择持有者，不出现无意义的比较符或自由文本道具名。指标比较运算随指标类型限定；高级 JSON 模式可编辑完整原始结构。切换模式、tab 或重置不得吞掉未知字段。不得保存空 `all`/`any` 子组；类型切换时清除旧类型专属字段，不能留下混合条件对象。

现有 NPC/玩家规则页只增加本轮必要的剧情事件绑定：可在效果中添加/选择 `recordStoryEvent`，并以共用条件编辑器编辑 `when` 等条件；其他未表单化的复杂效果继续由 JSON 模式处理，不在本轮重做完整规则编辑器。已保存的剧情事件列表刷新后，规则与图鉴页面的选项同步更新。底部保存与重置只作用于当前配置项，保存失败、引用缺失和版本冲突保留本地草稿。

## 图片资源与权限

复用封面上传的鉴权、项目归属、5 MB 上限及 PNG/JPEG/WebP 内容校验，但资源关联从“仅 manifest 封面”扩展为“项目图片”：道具图片引用写在 `items.json`，私有草稿可由作者预览，公开接口只提供已审核发布故事实际引用的图片。选择文件不立即保存；点击该页保存时先上传，再保存修改后的配置；配置保存失败则清理未引用上传，孤儿清理同时覆盖道具图片。不得接受任意外部 URL、SVG、路径遍历或别的项目的资源 ID。删除道具或移除图片后的孤儿文件通过安全清理回收，不在切换 tab 时删除仍被已保存内容引用的资源。

## 现有内容与校验

《sword-and-screen》的 `knows-kendo` 迁为一个有 UUID 的剧情事件：`ask-kendo` 的效果记录它，地点、人格和结局条件按 UUID 引用。`confession` 的效果显式记录“曾向苏念表白”的剧情事件，`confession-again` 不再以 `completedEvent` 为作者条件；已有“关系记忆”标签可继续服务人格描写，也可在迁移中统一改为剧情事件条件，避免无意保留两条相互矛盾的事实来源。旧的 `setFlag/flag`、面向作者的 `completedEvent` 条件在新剧本格式中移除，内部 `completedEvents` 保留。旧存档不做数据迁移；内容指纹不符时继续按现有机制判定为不兼容，不静默解释为新事件。

剧本装配、发布审核和本地 `loadScript` 必须同样读取 `storyEvents`；模板复制、新建空白剧本、发布冻结内容和内容指纹都必须包含它。校验 ID 唯一性、新建 ID 的 UUID 格式、非空 `label`、字符串类型的 `detail`（允许空字符串）、条件及效果对有效定义的引用、道具图片资源归属与 URL 形态。错误指出配置项和具体条目。定义顺序变化不影响 ID 关联。

## 验收与验证

1. 新建剧情事件生成 UUID；规则效果和条件选项只来自故事设定；删除被引用的事件时有明确错误。玩家动作成功后事件恰好记录一次，后续条件可命中，`NOT` 条件反向成立；失败规则、AI 提议但被拒绝的规则、未提交请求都不留下事件。
2. 同轮有效效果、自动规则、图鉴检查以及落库顺序与现有机制一致；重复事件、仅事件效果、混合多效果、部分目标缺失、修订冲突分别有测试。`completedEvents` 的 `once` 行为不回归。
3. 道具/结局/成就 tab、字段控件、上传预览、条件树编辑及 JSON 往返不丢内容；嵌套 AND/OR/NOT、道具持有者、类型相关比较和无效引用有测试。
4. 作者私有草稿图片不能由未授权访问或公开端读取；通过审核后玩家能看到道具图片。执行测试、类型检查、构建，并用窄屏/桌面浏览器人工核对创作流程及完整苏念剧情。
