# NPC 创作表单改造设计

## 目标与范围

作者可在 NPC 的「基本信息」「世界书」「性格行为」三个页面完成常用配置，不再手写 JSON、编辑内部 ID 或面对任意加字段入口。保留现有创作中心的米色背景、深色文字、左侧条目导航、紧凑 Ant Design 控件和「保存／重置」语义。本次不改变玩家端的角色头像展示方式，也不清理已有剧本中的高级字段。

## 基本信息

- 表单只呈现名称、描述、初始地点与初始道具。隐藏内部 `id`、`portrait`、`accent` 和任意「添加字段」入口。隐藏字段保存时原样保留；JSON 模式仍可查看。
- 描述使用多行输入；初始地点使用 Ant Design Select，选项来自当前草稿的地点列表。
- 初始道具沿用「地点道具」的模式：添加按钮打开弹窗，从当前道具列表选取；弹窗支持一次多选。添加后以道具 tab 切换，每件道具可单独「从 NPC 移除」。不呈现原始 ID 或 JSON。添加时排除已由地点或其他 NPC 初始持有的道具，以免引擎初始归属冲突。
- 每件道具在 tab 内提供「玩家可见」开关和「可见条件」，使用地点道具同款条件树、设置／清除操作。关闭开关时从 `itemVisibility` 删除该项；打开且无条件时写入 `itemVisibility[item] = null`（始终可见）；打开并设置条件时写入条件。新添加的道具默认打开；旧数据中没有 `itemVisibility` 项的道具维持关闭，不因打开表单自动变成可见。游戏过程中已被玩家发现的 NPC 道具仍按现有逻辑可见。
- 从初始道具中移除某项时，同步移除该项的可见配置，避免无效引用；其他未呈现的 NPC 高级配置不受表单更新影响。

## 世界书

- 条目使用新增按钮置于左侧纵向 tab 上方的布局；右侧只显示当前条目。每项为名称、类型（常驻／触发）、触发词标签和多行内容，可删除。ID 在新建时生成 UUID，不显示、不允许表单编辑。
- 新增 JSON 字段 `name` 与 `type: 'always' | 'triggered'`。旧条目没有 `type` 时，`keywords` 非空视为「触发」，空数组视为「常驻」；旧条目没有 `name` 时仅用首个触发词或「未命名世界书」作界面标题，不在加载时擅自改写数据。保存其他字段后可写入显式类型与名称。
- 常驻条目在其现有 `when` 条件通过时始终送入 AI 上下文；触发条目需同时满足 `when` 与最近话题包含任一触发词。触发条目至少有一个非空触发词才能提交审核。既有 `when` 条件保留在数据中，表单本次不新增其编辑入口；JSON 模式仍可编辑。
- 标签输入接受回车和空格提交；提交文本中若含英文或中文逗号，按逗号拆成多个标签；去首尾空白、丢弃空项、避免重复。已有标签可逐个删除。内容使用 textarea。去掉「添加字段」。

## 性格行为

- 使用与规则、道具相同的左侧纵向 tab，新增按钮在最上方。`id === 'common'` 的通用性格固定列首且不可删除；其余性格可删除。新增条目 ID 为 UUID，既有 ID 保留但不呈现。
- 每项只呈现名称、多行内容与条件；通用性格不显示条件，其余条目使用现有规则同款 AND／OR／NOT 条件树，可留空。保留原始数组中的其他未呈现字段。去掉任意「添加字段」。
- 若旧数据缺少通用条目，界面提供创建通用条目的入口；不因打开页面自动保存或修改草稿。

## 数据流与校验

- 表单只修改当前 tab 的内存草稿；点击页面底部「保存」后，按现有节区 API 将完整 JSON 存入后端。重置恢复该 tab 上次保存的内容。
- 后端继续原样存储 NPC 的 `base.json`、`lore.json` 与 `personas.json`，审核快照与发布内容保留新字段；不需要数据库迁移。
- 世界书新类型的运行逻辑、旧数据推断和触发词校验由脚本／AI 层处理，不依赖前端隐藏字段的偶然值。NPC 道具可见条件继续复用现有引擎判断。
- 测试覆盖表单无 ID／无添加字段、字段保留、初始道具添加／移除与可见条件联动、旧道具可见语义、标签拆分、旧世界书兼容、常驻与触发命中、通用性格固定与条件编辑，以及保存到审核发布的数据保留。
