# 创作中心表单易用性改造

## 目标与范围

第一轮先把「故事设定」和「地点」改成真正可用的结构化表单，沿用现有米白、深蓝、赭色视觉体系及固定顶栏、左侧配置导航。可以选用 Ant Design 的输入、下拉、上传、弹窗、标签等控件，但不把整站换成默认 Ant Design 风格。其他配置页暂时保留现有编辑器，统一改成显式保存。`spots` 和地点物品配置本轮不做可视化编辑；原有数据必须保留，仍可在 JSON 模式查看和编辑。

本规格替代此前创作中心设计中「空闲或切换标签自动保存」的约定：用户明确要求只有点击「保存」才修改服务器草稿。

## 编辑与保存边界

- 每个配置项有本地编辑草稿、最近一次已保存内容和修订号。编辑只改变浏览器里的草稿；底部固定提供「重置」与「保存」。重置回到该配置项最近一次成功保存的内容，须确认将丢弃未保存修改。
- 切换左侧配置项、返回故事列表、切换审核页、退出登录或关闭／刷新页面时，如当前配置项未保存，阻止无提示离开。站内提供「保存并继续／放弃修改／继续编辑」三种选择；浏览器离开使用原生未保存提醒。
- 校验与提交审核不隐式保存。若当前配置项有未保存修改，先提示保存；校验和提交只针对服务端已保存版本。保存仍使用修订号防止并发覆盖；冲突保留本地输入并提示重新载入或手动处理。
- 地点内层标签同属一个 `locations.json` 草稿；切换地点标签不提交服务器，也不丢失其他地点尚未保存的编辑。重置回退整个地点配置项。
- 表单模式和 JSON 模式使用同一份本地草稿，互切不自动保存；JSON 无法解析时保留原文并提示，不能强行切回会覆盖它的表单。

## 故事设定

- 表单只显示标题、副标题、简介、世界背景、封面、开局地点、时间段。`id`、`version`、`theme` 在表单隐藏但保留底层值；本页不显示「新增字段」。简介和世界背景使用多行输入。
- 新建故事只输入名称和可选模板；故事 ID 由服务端生成全局唯一且不可变的值，复制模板时也换成新 ID。`version` 继续由系统维护，不要求作者填写。
- 封面使用图片上传控件，有选择、预览、移除状态；选择文件不会立即修改服务器。点击保存时上传并关联该故事的封面。服务端校验登录身份、所属项目、图片格式与大小，只允许 PNG/JPEG/WebP，不允许 SVG 或任意文件路径。上传成功后播放器目录使用图片显示封面；旧故事的文字封面继续兼容。上传中断、校验失败或配置保存冲突时保持表单可重试，不假称已保存。
- 开局地点使用单选下拉，选项来自该故事**已保存**的地点列表：展示地点名称，实际保存地点 ID。地点页新增／改名／删除并保存后，下拉选项刷新；未保存的地点不出现在此处。若现有开局地点 ID 找不到匹配项，显示明确的无效引用提示，不自动改写。
- 时间段显示可排序标签；点击已有标签弹出编辑弹窗，可改名、删除。点「新增时间段」弹出输入弹窗。可用明确的上移／下移操作调顺序；至少保留一个，删除最后一个时按钮禁用并解释原因。空白故事默认「白天、下午、晚上」；已有故事时间段原样保留，不做静默迁移。

## 地点

- 地点页顶部为内层标签：每个地点一个标签，显示名称；末尾提供「＋ 新增地点」。切换后只显示该地点的表单，避免把所有地点纵向铺开。新增地点生成稳定且唯一的 ID，作者在表单无需填写或修改；保存后该 ID 用于其他配置引用。
- 地点表单先显示名称、交流方式、简介／描述。交流方式保留现有 `interactionMode` 机制，用可读选项「线上」「面对面」，不使用原始字符串输入。描述使用多行输入。删除地点需明确确认；若被开局地点或其他已保存配置引用，保存／校验时应给出可定位的引用错误，不能悄悄重定向。
- `spots` 暂不做；`items` 与调查点／获取条件的可视化设计等物品页确定后再做。表单编辑或保存地点时必须保留这些字段原值；JSON 模式仍能完整编辑。

## 布局与反馈

- 保留固定顶栏和左侧主导航；中间编辑区顶部显示清晰的页面标题、简短说明及「表单／JSON」切换，地点子标签紧贴地点标题下方。表单以单列或有语义的双列分组排版，长文本占满编辑宽度，不再把所有结构字段堆成文本框。
- 「保存／重置」位于每个配置页底部的可见操作栏，显示待保存、保存中、已保存、失败、修订冲突状态。窄屏操作栏和子标签仍可使用；按钮不会被横向滚动遮住。
- 字段错误就近展示；未保存、上传失败、引用无效与保存冲突用不同文案，不混用“已保存”。

## 数据与接口

- 继续使用既有 `manifest.json`、`locations.json` 等剧本结构，不为 UI 新增一套并行配置。服务端生成故事 ID；地点 ID 在新增动作时生成，保存前留在本地草稿。旧故事 ID、地点 ID 及引用保持不变。
- 封面采用项目关联的受控图片资源；图片文件存储在服务端数据目录，数据库／剧本配置只保存可解析的资源引用。公开游玩端只可读取已发布故事引用的封面，作者可以预览自己的草稿图片。服务端必须限制文件大小、格式和项目权限，避免暴露草稿或路径遍历。资源写入和 manifest 保存失败的清理策略需在实现中明确，不能无限留存孤儿文件。
- 发布仍使用现有整部剧本校验和冻结快照。表单层的隐藏字段、未实现的 `spots`／`items` 不能在保存时被剔除。

## 验收

- 新建故事不要求填写 ID；地点页能新增、切换、编辑地点，故事设定能以名称选中已保存地点并把 ID 写入开局配置。
- 修改任一配置页不会自动发保存请求；只在点击保存后持久化。重置、站内离开、浏览器离开、JSON／表单切换均不会静默丢失编辑。
- 时间段可增删改序，只有一个时不能再删；默认三个。封面可上传、预览、保存，在玩家目录显示；非法文件被拒绝。
- 编辑地点表单后原有 `spots`、`items`、未知扩展字段以及故事设定隐藏字段仍完整；旧故事无需迁移即可加载。
- 并发修订冲突、上传失败、无效开局地点均有明确反馈；相关单元／集成测试以及前后端构建通过，关键流程在窄屏浏览器检查。
