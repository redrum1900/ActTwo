# 玩家与创作者统一账号设计

日期：2026-10-03

## 目标与已确认边界

同一账号既可游玩，也可创作故事。任何注册账号都可进入创作中心；只有 superadmin 可审核故事、查看所有人的 AI 调用记录、使用智能导入。正式游戏必须登录才能开始、继续、行动、聊天或读写存档；未登录者可以浏览公开故事。旧访客存档不迁移，旧访客身份不再用于游戏授权或数据归属。

## 当前状态与选择

目前 `creator_accounts` 与 `creator_sessions` 只保护 `/api/creator`，正式游戏通过 `gd_guest` Cookie 将存档和图鉴绑定到浏览器。选择扩展已有账号／会话作为平台统一身份，不另建一套玩家账号，也不把访客 ID 当作登录账号。保留现有 `author` 与 `admin` 角色语义：普通注册账号即 `author`，既能玩也能创作；`admin` 即 superadmin。

## 会话和权限

- 登录／注册／登出使用同一套账号和会话；会话 Cookie 对正式游戏及创作中心 API 都可用，保持 HttpOnly、SameSite、生产环境 Secure。更改 Cookie 作用路径时同步核对登出清除、旧 Cookie 和跨页面刷新行为。
- 正式游戏的创建、读取、列表、手动／自动存档、图鉴、行动、聊天及流式聊天都从已验证会话取得 `account_id`，由服务端作为 owner。客户端传来的 owner ID 一律不能作为授权依据。
- 创作中心继续检查项目归属；审核、智能导入和全站用量接口额外检查 `admin` 角色。仅隐藏前端入口不足以授权。
- 未登录访问需要游玩状态的 API 返回 401；公开故事目录和已发布故事的公开介绍可继续浏览。账号切换后，不能读到上一个账号的存档、图鉴或 AI 调用记录。
- 对所有会改变数据的账号请求沿用同源检查或等效 CSRF 防护，避免扩大 Cookie 作用域后引入跨站写入。

## 数据迁移和旧数据

`save_slots`、`gallery` 等已有 `owner_id` 列保留，但新记录只写账号 ID。旧 `gd_guest` 记录不认领、不自动合并、不作为可访问存档；此次不执行清库或物理删除。既有已发布版本快照不受账号迁移影响。新建游戏仍取最新已发布版本，继续旧的账号存档仍按存档所绑定的版本读取。

## 接口与界面

游戏首页提供登录／注册入口和当前账号状态；未登录点击开始或继续时引导登录，登录后再执行原操作。创作中心复用同一会话，不要求第二次登录。账号菜单提供退出登录和“我的 AI 用量”入口；superadmin 另有全站用量入口。具体用量内容由调用记录设计定义。

## 验证

- 未登录可浏览但不能开局、继续、行动、聊天或读取存档；登录后正式游戏与创作中心均可用。
- 两个账号的存档、图鉴、项目和调用记录互相隔离；切换账号或登出后不得泄露前一账号数据。
- `author` 不能使用审核、智能导入或全站调用记录 API；`admin` 可用。
- 旧访客 Cookie 不授予游玩权限，旧存档不会被误认领；正式版本绑定的存档语义保持不变。
