# Superadmin 单次 AI 智能导入设计

日期：2026-10-03

## 目标与边界

在已有故事中导入小说或角色卡，使用一次模型请求生成完整配置，写入该故事当前草稿，再由 superadmin 人工检查和修改。不追求 AI 自动解决全部矛盾；不为复核、修复、分段摘要或自动重试额外消耗模型调用。支持现有 `txt`、`md`、`doc`、`docx`、`json` 素材；上传前不加字节数限制，但模型无法处理过长内容时明确失败，不截断或隐去部分原文。

## 权限与覆盖

智能导入入口和全部导入 API（上传、进度、结果、应用、取消）仅对 `admin` 角色开放，登录且具有当前故事编辑权限也是必要条件。导入当前已有内容的故事时，在**写入前**明确提示会替换全部当前草稿配置，并要求确认；未确认或用户取消不能改动草稿。覆盖只影响草稿，不改变已发布版本、待审快照或现存试玩快照。导入成功返回当前故事 ID，保持作者继续编辑的上下文。

## 单次生成与结果处理

1. 提取文件文本、读取现行小说／角色卡转换规则，组合成一次模型请求。长素材不再走分段 AI 摘要。连接失败、超时、输出截断或模型拒绝过长输入，均按本次失败提示；不自动切换模型或重试。用户手动再次点击属于新一次导入操作。
2. 模型返回后只做本地、确定性处理：JSON 解析、确认可安全拆成受支持的配置路径、固定当前故事 ID 与草稿版本、检查路径与实体 ID 安全性、列出结构和引用问题。不要调用 AI 做叙事复核、矛盾检查或修复。
3. 无法解析为 JSON、缺少可拆分的故事对象或存在不安全路径／重复实体 ID 等无法安全写入的问题时，导入失败且草稿不变。可安全拆分但缺字段、引用错误或暂时不能运行时，仍可应用到草稿；缺失模块保留可编辑的空配置，不凭空补写剧情，并展示确定性错误清单供人工修正。
4. 应用结果时在一个数据库事务中替换当前故事的全部草稿配置；若草稿在生成期间被修改，要求用户重新确认最新覆盖目标，避免静默覆盖新编辑。确认应用后的草稿允许保存为不完整状态。

## 提交审核与试玩

草稿保存不要求可运行。提交审核和开始试玩都执行现有确定性运行校验，错误时指出具体配置路径并阻止该动作；不调用 AI 审核或自动修改配置。导入报告与可运行性错误是作者编辑辅助，不承诺故事逻辑或叙事无矛盾。

## 与调用记录的关系

唯一一次上游请求也写入 AI 调用记录，归属当前 superadmin 账号、故事与 `import` 来源；失败且服务商不提供 token 时记录未知用量。导入的文件正文、提示词和模型输出不进入调用审计表。

## 验证

覆盖所有支持的文件格式、长输入、模型失败、输出不是 JSON、可拆分但结构无效、路径或 ID 不安全、并发修改草稿、确认覆盖与取消。断言一次导入最多发出一次模型请求，不执行 AI 复核／摘要／重试；普通账号对所有导入接口均被拒绝；失败不改草稿，成功只改草稿且返回故事 ID。
