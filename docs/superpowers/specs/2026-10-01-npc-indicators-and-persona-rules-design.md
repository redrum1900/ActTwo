# NPC 指标、规则与条件角色描述：苏念可玩样例设计

## 目标与范围

把苏念剧本做成可游玩的新机制样例，验证复杂角色卡能否用通用配置表达，而不依赖引擎内置的顺序 `stage`。玩家仍可在家中通过电脑与苏念线上聊天，之后解锁饭店和苏念家；语义事件、好感、道具、NPC 在场地点、资料可见性和结局仍由后端规则决定。AI 同时扮演当前角色并识别玩家话意，但不能自行写入游戏状态。

本次实现通用的指标／条件／效果能力，并用苏念完整迁入、端到端试玩验证。旧《雾港来信》可暂由旧加载路径运行，不为它新增阶段行为；创作者中心、账号、线上剧本分发和图形编辑器不在本次范围。JSON 与将来网页编辑器共用一份校验后的配置契约，网页编辑引用 NPC／指标／物品时应使用选择器。

## 已比较的方向

1. 保留 `stage`，继续叠加修饰条件：改动小，但特殊分支、不可逆状态和每 NPC 差异仍须在阶段引擎中做特例。
2. 全部由 AI 根据完整规则文本判断：配置看似简单，但数值、道具归属和跨 NPC 条件不可可靠执行，也会增大提示词。
3. **采用通用指标＋后端规则＋派生快照**：剧本显式描述状态变化；AI 只处理语义和角色表达。苏念的旧阶段成为指标与不可逆标记的组合，而非通用引擎类型。本方案被选中。

## 配置结构

NPC 目录继续拆分文件：`base.json` 为身份与基础角色描述，`indicators.json` 定义该 NPC 的指标，`personas.json` 定义条件角色描述，`rules.json` 定义当前 NPC 的规则，`placements.json` 定义可互动地点和线上／当面方式；`profile.json`、`lore.json`、道具和地点文件继续按现有包加载。每条人格配置是一段**完整文本**，创作者自己同时写性格、行为、心理和语气，不拆字段并自动拼接。基础描述始终存在；若没有条件人格命中，快照使用基础描述；若有命中，则完全替换基础描述，并按 JSON 顺序把所有命中条目作为有名称的文本块送给 AI。系统不判断其内容是否矛盾，内容质量由创作者负责。

配置形状示意（完整苏念文案在实际迁入时保留，以下只展示字段关系）：

```json
{
  "indicators.json": [
    { "id": "affection", "name": "熟悉度", "type": "number", "initial": 0, "min": 0, "max": 100, "playerVisible": true },
    { "id": "metInPerson", "name": "已见面", "type": "boolean", "initial": false, "playerVisible": false, "writeOnceTrue": true }
  ],
  "personas.json": [
    { "id": "online", "name": "屏幕两端", "when": { "not": { "indicator": { "id": "metInPerson", "eq": true } } }, "content": "此处为完整的线上角色描述" }
  ],
  "rules.json": [
    { "id": "close-talk", "trigger": "semantic", "intentDescription": "玩家真诚表达亲近，不包括普通问候", "positiveExamples": ["我很在意你的感受"], "negativeExamples": ["你好"], "once": false, "effects": [{ "type": "changeIndicator", "id": "affection", "by": 3 }] },
    { "id": "meet", "trigger": "automatic", "once": true, "when": { "indicator": { "id": "affection", "gte": 30 } }, "effects": [{ "type": "setIndicator", "id": "metInPerson", "value": true }] }
  ],
  "placements.json": [
    { "locationId": "player-home", "channel": "online", "when": { "not": { "indicator": { "id": "metInPerson", "eq": true } } } }
  ]
}
```

上例以各个文件名作说明键，并非实际要合并成一个 JSON 文件。`indicator` 条件在 NPC 自己的文件中默认读取自己；要读另一 NPC，显式写 `npcId`。`rules.json` 的效果同理，未写目标时默认修改所属 NPC。

指标定义包含稳定 `id`、名称、类型、初始值、初始 `playerVisible` 及对应类型约束。第一版类型为：有上下界的数字、选项受限的枚举、布尔、去重无序的标签集合、文本。文本值只由规则设置为创作者预设内容，不让 AI 自由写入并用于精确比较。部分布尔指标可声明 `writeOnceTrue`，运行时一旦为真便不可设回假。指标的运行时值与当前 `playerVisible` 都在真实存档里；规则可显示或隐藏指标。隐藏的值仍参与规则和当前 NPC 对话，但玩家资料页、变动提示及玩家游戏日志不泄露隐藏数值；后来揭示时只显示当前值，不补发历史变化。

条件由原子判断和递归 `all`／`any`／`not` 组成。原子判断按类型提供数值大于／小于／等于，枚举／布尔相等或不等，标签包含或不包含；保留时间、地点、道具（含标签）、已完成事件、地点开放等现有判断。NPC 自己的规则可省略目标 NPC ID；引用其他 NPC 的指标必须使用明确 `npcId`。加载／导入时校验 NPC、指标、道具、地点和事件引用，不允许拼写错误静默成为永不触发的规则。异常旧运行数据中的未知引用安全跳过并记录服务端诊断。

规则明确区分语义事件、每次有效操作后自动检查的规则、玩家明确动作的效果。每条规则可有 `candidateWhen`、生效 `when`、`once` 或可重复、优先级／互斥组、原子 `effects`、成功／受阻回复提示以及可选正反语义例子。效果至少能改变指标值或可见性、添加／移除标签、移动或发现物品、解锁地点／NPC、记录图鉴。多个兼容事件可同轮执行；互斥组按优先级选择，效果不能半成功。数值受指标上下界约束。

一轮语义事件的门槛统一基于**轮次开始前**的真实状态计算；AI 提议的 ID 只是候选，服务器重新验证 NPC、条件、once、互斥和效果。成功事件的效果落地后，每条自动规则基于同一轮效果后快照检查一次，不在同轮循环执行新规则链；随后重算人格、在场地点、地点可见性、图鉴及玩家视图。条件人格和在场地点是计算结果，不是第二份可独立修改的事实。多个地点条件同时命中时按配置顺序取第一条，并在作者诊断中记录冲突；一个 NPC 在玩家视图中至多有一个互动地点。

## 苏念映射

苏念至少有 `affection` 数字指标，`metInPerson` 与 `visitedHerHome` 等 `writeOnceTrue` 布尔指标，以及需要的标签集合。线上人格条件为 `not metInPerson`，饭店人格条件为 `metInPerson and not visitedHerHome`，家中人格条件为 `visitedHerHome`；它们的文本取自原三阶段完整角色卡。旧 `modifiers`、`knowledgeBoundary`、相关 `lore` 和 `talkingPoints` 要合入适合的完整人格／话题材料，不因字段迁移而丢失角色细节。第一阶段只在玩家家中电脑入口可互动，AI 快照明确标注“线上”，不能误写成苏念本人站在玩家家里；后两处分别在饭店和苏念家可互动。

原有所有苏念事件逐一映射；普通闲聊不自动加分，像“认真表达亲近”“分享共同经历”“给她空间”这样的语义规则由 AI 判断玩家话意，后端按作者配置加分。`affection >= 30` 后的自动规则写入 `metInPerson=true` 并开放饭店；`affection >= 60` 且已见面后写入 `visitedHerHome=true` 并开放苏念家。写一次的标记阻止好感下降造成退回；以后特殊分支可通过新的持久布尔指标及 `not` 组合表达。原截图、剑道御守、旧照片、训练笔记的发现／获取／转移条件，以及图鉴结局改引用新指标并保持原意。所有旧阶段 ID 和旧邀约提示不再进入苏念 AI 快照或玩家 UI。

## 真实状态、快照与 AI

存档是唯一真实状态：指标值／可见性、背包物品唯一归属、地点和解锁、事件完成记录、对话、游戏日志。`NpcSnapshot` 是每次操作结算后按剧本派生的只读投影，包含当前指标、有效完整人格文本、互动地点／线上线下方式、背包和当前可披露角色知识；它可缓存但不能被规则或 AI 直接写入。当前轮生成回复使用操作前快照；这一轮的效果会影响下一轮人格。若结算使草稿与真实道具、地点或事件结果矛盾，后端调用修订并只保存最终回复，修订仍保持本轮操作前的人格语气，只纠正已结算的事实。

每次只把当前 NPC 的相关快照、当前玩家可被其合理知晓的资料和物品、地点／时间、当前话题相关知识，以及保留关键信息的压缩对话上下文发给 AI。当前命中的完整人格优先保留，旧对话可摘要但原聊天不从存档删除。AI 只拿经后端筛选的当前 NPC 候选语义事件 `id`、描述、正反例、`canApply` 和安全的成功／受阻提示，不拿完整条件与效果 JSON，也不拿其他 NPC 的原始状态。跨 NPC 条件由后端按 ID 查询；AI 只能获知该角色在剧本中合理知道的事实。预期返回 `{ message, proposedEventIds }`，不接受模型给出的数值、物品归属、可见性或“切阶段”决定。

AI 草稿可流式预览，但不作为事实写存档。服务端核验并结算事件后，凡实际状态改变、候选被拒或人格／在场地点变化可能使草稿失实时，按真实结算结果进行必要修订；普通闲聊仍尽量只调用一次 AI。若 NPC 本轮离开玩家当前互动地点，先显示最终回复和变化提示，再关闭聊天返回当地 NPC 列表。失败或无效回复不提交正式聊天、指标、日志或自动档。

## 玩家视图、诊断与旧数据

玩家界面只显示当前 `playerVisible=true` 的 NPC 指标和实际可见的道具、地点、资料；隐藏指标的变化不以精确数值出现在玩家提示或日志中。游戏日志仍记录玩家操作和实际可公开的结果；创作者另有本人的测试会话诊断，能看到候选事件 ID、接受／拒绝原因、规则效果及地点条件冲突，不向普通玩家泄露内部条件，也不默认开放其他玩家私聊。

本阶段无正式用户。新配置启用时不编写旧存档迁移：当前项目的旧自动档、手动档及旧图鉴记录都将作为测试进度清理；不会触碰其他项目或账号数据。实际删除前须只读确认当前项目数据库、表及记录数量，列出精确目标并保留可恢复的数据库备份；设计文件本身不执行删除。保留苏念剧本内容并转换配置，旧《雾港来信》只作过渡兼容，不影响苏念样例验收。

## 验证标准

苏念样例须可通过自由对话从线上人格进入饭店、再进入家中人格；不同轮次语义识别才加分，重复／一次性规则按配置运行；写一次标记保证不退回；当前轮回复沿用旧人格，下轮采用新人格；线上互动不误写实体同处。一次操作中事件门槛读操作前状态，自动规则只跑一层，派生人格／地点立即刷新。背包与隐藏道具、动态指标可见性、跨 NPC 条件和未知 ID 校验均由规则测试覆盖。记录真实事件及创作者诊断；AI 只收到当前快照及相关候选摘要。已有聊天流式、自动存档、手动槽位与顶部固定布局保持可用。完成自动测试、构建和苏念实际游玩后，再由用户评审效果。
