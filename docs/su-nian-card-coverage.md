# 苏念角色卡对接审计（指标版）

来源：用户提供的 `chara_card_v3` 备份。角色卡是创作参考，不作为系统指令原样注入 AI。此表区分“供 AI 表达的描述”和“后端可验证的效果”。

| 角色卡要素 | 当前配置与行为 |
| --- | --- |
| 线上、饭店、她家三种性格、行为、心理、语气和场景 | `npcs/su-nian/personas.json` 的通用人格叠加当前命中的条件描述；稳定事实只写在通用段 |
| 告白后更留意玩家、剑道经历被理解后主动谈训练、读过笔记后更坦白 | 同文件另外三项条件人格；与普通版本互斥，避免拼接相互矛盾的描述 |
| 电脑私聊，之后到饭店与她家面对面 | `base.initialLocationId` 与规则的 `moveNpc` 管 NPC 位置；`locations.json` 管地点互动方式与玩家访问 |
| 好感、已见面、到过她家、关系记忆 | `indicators.json`；好感数值与布尔、标签集合都在存档运行值中，两个里程碑布尔设为 `writeOnceTrue` |
| 分享截图、告白、体贴、调侃、给她空间、接纳两面、谈剑道、读笔记等 | `rules.json` 的语义规则；AI 只建议事件 ID，后端检查 `when`、once、互斥及效果；普通闲聊不无条件加分 |
| 好感达到 30／60 开放新互动地点 | `rules.json` 的 `automatic` 规则设置不可逆指标并移动 NPC；`locations.json` 根据指标开放地点，无内置阶段切换 |
| 截图、御守、照片、训练笔记 | `items.json`、地点物品和规则；发现／获取分离，唯一归属与标签保存在存档，不回写静态文件 |
| 剑道秘密、家中信息、话题边界 | `lore.json` 的条件门槛和 `personas.json` 的情境描述；早期 AI 输入不发送剑道秘密与隐藏御守 |
| 结局后继续聊天 | `endings.json` 记录达成状态，对话仍可继续 |

旧 `stages.json` 和角色目录下的 `events.json`，以及空的全局 `events.json`、`stats.json` 已删除。当前实际玩法只依赖新文件。原卡中无条件增加好感、无限生成物品或跳过双方意愿的描述没有迁入，因为它们与后端确定性结算和用户确定的游戏边界冲突。

## 文件与规则约定

NPC 在 `content/<story-id>/npcs/<npc-id>/` 拆分配置。`rules.json` 使用 `when` 表达真实门槛，`candidateWhen` 表达候选是否交给 AI；两个条件均可组合 `all`／`any`／`not` 与数值、标签、道具、时段等原子条件。引用其他 NPC 指标时写 `npcId`，引用自己的指标可省略。人格由真实状态派生；NPC 位置则是存档中的事实。隐藏指标仍影响规则与 AI，却不会在玩家资料和游戏日志显示精确变化。

## 试玩检查路线

1. 新游戏只开放「电脑上」；苏念通过电脑私聊。搜索并获取[并肩作战截图]。普通问候不会加熟悉度，分享截图、认真关心或告白才可能触发相关语义规则。
2. 熟悉度到 30 后，饭店开放，苏念从家中线上入口消失。当前消息仍按线上人格回复，下轮在饭店按初见人格对话；可核查游戏日志的地点开放记录。
3. 饭店里给她空间、谈两面与剑道。熟悉度到 60 后，她家开放。好感回落也不能让已见面或到访标记退回。
4. 在她家搜索：[旧照片]可发现但好感不足时取不了；[训练笔记]需已知剑道且持有截图才能发现，再达到获取门槛。获准阅读后笔记标签及人格心理变化。
5. 谈[剑道御守]并满足规则后核查道具从苏念转给玩家；达到结局条件后仍能自由聊天。玩家资料只显示当前公开指标。

模型文风与语义判断仍需真人试玩评估；指标、道具、地点及图鉴只以服务器实际结算为准。
