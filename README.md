# 叙事档案 · 剧本规则试玩版

一个由剧本配置驱动的网页版 AI 角色对话游戏。当前样例为《屏幕那端的剑道女生》。前端使用 React + TypeScript，后端使用 Node.js + Express，游客存档与创作者故事保存在服务器 SQLite 中。

## 启动

需要 Node.js 20 或更新版本。

```bash
npm install
npm run dev
```

终端会显示前端地址，通常是 `http://localhost:5173`。如端口已被占用，Vite 会显示实际使用的端口。后端运行在 `http://localhost:3001`。
开发服务默认只监听本机。游戏目录右上角可进入创作中心，或直接打开 `/creator`。创作者需注册用户名和密码；不同作者只能查看、修改自己的故事，游客游戏存档与创作者账号分离。

### 创作中心

在「我的故事」中新建空白故事，或复制内置样例。编辑器左侧按剧本、玩家、角色分组，点击每个配置项切换标签；修改会在短暂停顿后自动保存，切换标签、校验和发布前也会先保存。每项可在表单和原始 JSON 模式之间切换，复杂嵌套结构建议使用 JSON 模式。未完成或格式错误的 JSON 可暂存为草稿，但必须校验通过才能发布。

角色可在编辑器左侧新增和移除。每项保存都带修订号；同一配置项若被另一个标签页先修改，旧标签页会收到冲突提示，不会覆盖新内容。发布会冻结当时的剧本快照；之后编辑草稿不影响玩家目录，直到再次发布。删除故事会从玩家目录下架并隐藏草稿，不抹去玩家原有存档行和服务端历史发布记录。下架后玩家无法进入该故事；重新发布同一 ID 当前未提供恢复入口。

部署时运行 `npm run build`、设置 `NODE_ENV=production`，再运行 `npm start`。生产服务会同时托管前端资源与 API；请在 HTTPS 反向代理之后运行，并设置 `GAME_API_HOST=0.0.0.0`、稳定的 `PORT` 与强访问控制。创作者登录 Cookie 在生产模式下设置 `Secure`，因此正式环境须使用 HTTPS。定期备份整个 `data/game.sqlite`（以及 WAL/SHM 文件或使用 SQLite 在线备份），不要把数据库、`.env`、AI 请求日志公开为静态文件。公开注册若暴露于互联网，建议在反向代理上增加登录／注册限流与滥用防护。

没有配置模型密钥时，系统使用明确标记的“演示对话模式”：可测试话题触发、道具、数值、存档和页面流程，但角色回复是固定演示文本。要启用真实 AI，对照 `.env.example` 在项目根目录创建 `.env`，填写服务端密钥：

```dotenv
AI_API_KEY=你的密钥
AI_BASE_URL=https://你的兼容接口/v1
AI_MODEL=你的模型名称
AI_MEMORY_TRIGGER_CHARS=5000
AI_MEMORY_RECENT_CHARS=3500
AI_MEMORY_BATCH_CHARS=8000
AI_TEMPERATURE_GENERATE=0.7
AI_TEMPERATURE_UTILITY=0.2
```

密钥只由后端读取，不会发送到浏览器。接口支持兼容 OpenAI Chat Completions 的模型服务。实际可生成内容仍受接入服务的使用规则约束。

每次实际发给 AI 的请求（含重试）会追加一行到 `data/ai-requests.jsonl`。日志记录同轮 `turnId`、调用用途（判断/生成/摘要）、请求字符数、耗时、HTTP 状态和服务商返回的 token 用量；不会记录密钥、提示词或回复全文。服务商未返回 `usage` 时该字段为 `null`，不能据此推算精确费用。可通过 `AI_REQUEST_LOG_PATH` 修改日志路径；请将日志文件留在服务端，不公开提供下载。日志会持续增长，部署时需定期归档或清理。

AI 请求按用途设置生成温度，但不传 `max_tokens`，由模型服务决定默认输出长度。设置 `AI_CHAT_MODE=combined` 可启用试验性单请求模式：后端筛选可生效规则 → AI在一个JSON内返回 `message` 和 `proposedEventIds` → 后端校验、结算、保存。本轮台词使用结算前的状态，下轮才使用新的状态。规则类似预定义工具，AI只选择ID，不决定effects参数。流式仅展示message，完整结构校验通过后才保存；格式错误不自动补发判断或重写，不将普通文本默认为无事件。物品获得、NPC移动和地点解锁由系统通知展示。长期记忆摘要或429重试仍可能增加调用，均记录在同轮日志中。

默认仍为此前两步模式 `AI_CHAT_MODE=settled`：先语义判断、预结算，再生成最终回复。修改配置后需重启后端。两种模式都不会自动调用重写。`usage.cachedTokens` 记录输入缓存命中量，`finishReason` 可帮助判断模型端截断。单请求模式依赖模型遵守JSON契约，真实渠道仍可能格式失败；不能把自动化测试通过视为模型稳定性保证。

单请求模式长存档（82条消息、13103字符）三次实测：一次有效、两次格式校验失败，未修改真实存档。日志在 `data/ai-combined-probe.jsonl`；估算费用分别 $0.009728、$0.004205、$0.003763，失败请求同样收费。由于稳定性不足，没有将试验模式作为默认，也未自动补发付费修复请求。后续应验证渠道原生tool calling支持，而非宣称该JSON模式已稳定。

固定前缀试验：`createCombinedChatAdapter({ promptLayout: 'fixed-prefix', ... })` 把世界设定、通用人格、无门槛语义规则放进固定系统消息；快照移除重复世界设定及通用人格，末尾保留生效人格、数值、物品、可用规则ID和已解锁条件规则。不会提前发送受条件保护的规则或后续人格。此选项没有接入默认服务流程。

可用 `npx tsx scripts/probe-prompt-layout.ts --live` 复现实验（四次付费调用，429可能重试）；脚本只读数据库，在相同长历史下改变本轮消息和一个数值，不写存档。2026-10-01 四次对照日志为 `data/prefix-1790859022641.jsonl`，报告为同名前缀的 `-report.json`。旧布局第二次输入17387、缓存16896、输出388，估算$0.004354；固定布局第二次输入17496、缓存16896、输出7且格式失败，估算$0.003870，不能视为等质量省钱。固定布局首次缓存仅8192，格式有效但答非所问。样本太小且输出质量不同，未证明新布局降低成本。报告包含测试角色回复，仅供服务端本地查看。

运行 `npm run ai:cost` 查看最近10轮合计消耗（包括重试和摘要），也可用 `npm run ai:cost -- 日志路径` 分析单独测试。默认美元单价来自此前平台截图：输入0.8/M、缓存0.2/M、输出1.5/M；可用 `AI_PRICE_INPUT_PER_M`、`AI_PRICE_CACHED_PER_M`、`AI_PRICE_OUTPUT_PER_M` 覆盖。费用只是估算，不含汇率、充值折扣或其他渠道计费差异；缺失用量会明确标记，不能当作免费。

2026-10-01 两步流程早期两轮独立内存实测：每轮2次调用、无重写，估算分别 $0.004339 / $0.004196。判断请求仅620字符却由渠道返回8237输入token（缓存7680），额外计数来源待渠道核对。此样本不代表长历史成本。

### 对话记忆压缩

当前使用 `memory-policy.ts`，不再由旧 `AI_CONTEXT_CHARS` 控制实际发送的历史。每个NPC独立保存结构化长期记忆：facts、relationship、commitments、boundaries、openTopics。每条记忆带原始消息来源ID；发给角色模型时只传正文，不传来源ID。完整聊天原文不删，历次累积摘要作为可重建派生数据保留在 `memorySegments`。

长期记忆目标1200字符（校验上限1500字符正文）；记忆加未压缩原文超过5000字符时启动压缩，近期原文目标3500字符，至少保留最近4个完整轮次，长轮次不截断。每批旧消息目标上限8000字符，单个超长轮次允许超过。仅移除已有成功摘要覆盖的原文；摘要失败或尚未覆盖的历史仍发送，宁可临时超预算，不静默遗忘。角色设定、规则和快照不算在这个历史预算内。

正常对话保存后异步进行一批压缩，同一owner/game/NPC最多一个后台任务；不阻塞回复。首次读取没有有效结构化记忆的长档，会先准备一批记忆再回复。两类摘要均计入触发对话的turnId费用。来源、分类、长度校验失败时保留旧记忆，间隔5个该NPC成功对话轮次再试。AI摘要的语义准确性无法仅靠来源ID校验保证，需在实际游玩中核对重要承诺和关系信息。

后台结果只在存档revision与完整原状态仍匹配时写入；新游戏、读档、任何新操作会使旧任务失效。写入只更新派生记忆，不增加游戏revision，避免前端凭空遇到版本冲突。服务器重启会终止未完成后台任务，原文不会丢失，下次满足条件后再生成。初始压缩本身有一次性费用，必须用多轮平均费用评价效果，不能承诺第一轮立即更便宜。

AI 上游请求发送 `stream: true`。玩家发言立即显示；NPC 回复作为临时文字逐字出现，规则结算后可能被最终修订稿替换。若请求失败，玩家原话保留为“发送失败”，可用同一个对话轮次 ID 重试。游戏内的“游戏日志”随存档保存每次实际操作，以及可公开的指标、道具、地点等结果；读手动档时会一起回退。

本地开发需要排查语义规则时，可设置 `GAME_DEV_DEBUG=1`，用当前游客身份访问 `/api/games/<game-id>/debug` 查看该存档的提议、接受、拒绝及原因。接口默认关闭，生产模式强制关闭；普通游戏响应不包含内部规则 ID 或隐藏指标诊断。

## 代码模块

```text
apps/web/                 React 页面、交互与样式
apps/web/src/creator/     独立创作中心：账号、项目列表、配置项编辑
apps/api/src/app.ts       HTTP 接口与游戏操作编排
apps/api/src/creator/     创作者身份、草稿配置项、发布版本与接口
apps/api/src/script-repository.ts  内置及已发布剧本的统一读取
apps/api/src/chat-service.ts  对话事务：结构化回复 → 规则结算 → 必要时修订
apps/api/src/ai-adapter.ts    模型服务适配与演示模式
apps/api/src/ai-stream.ts     AI 上游 SSE 解码与回复文字提取
apps/api/src/memory-policy.ts  结构化记忆、整轮选取、来源校验和冷却
apps/api/src/memory-worker.ts  后台记忆压缩与过期任务隔离
apps/api/src/save-store.ts    SQLite 自动档、手动档和图鉴
packages/contracts/      剧本、游戏状态与规则类型
packages/engine/         不依赖 AI 或数据库的纯规则引擎
packages/script/         剧本包加载与引用校验
content/sword-and-screen/  苏念多文件 NPC 试玩剧本
tests/                   规则、剧本、存档和 API 测试
```

浏览器只收到当前可见的地点、人物资料和道具。角色隐藏设定与剧本规则保留在服务器。每个游戏独立拥有一个自动档和五个手动槽位；读入手动档会立即覆盖该游戏的自动档。结局与成就保存在存档之外。

## 修改或新增剧本

普通作者推荐通过 `/creator` 配置和发布故事。下述文件结构仍适用于内置内容包与开发者直接维护的样例。

复制 `content/sword-and-screen/` 为新的 `content/<story-id>/` 目录，并修改 `manifest.json` 的 `id`。平台目录会自动发现新目录。剧本的基础文件是：

- `manifest.json`：游戏信息、版本、起始地点、时段和世界设定
- `player-form.json`：新游戏玩家资料表单
- `items.json`：道具
- `locations.json`：地点、可见／进入条件、互动方式、调查点及地点物品
- `endings.json`、`achievements.json`：图鉴条件

NPC 按 `npcs/<npc-id>/` 拆分：`base.json`、`indicators.json`、`personas.json`、`rules.json`，按需添加 `lore.json`。`base.initialLocationId` 定义开局位置，之后只由规则的 `moveNpc` 效果移动；当前位置保存在存档中。`locations.json` 的 `visibleWhen` 决定地点何时对玩家出现，`enterWhen` 决定当前能否进入，`interactionMode` 决定线上或当面交流。这些都在同一份地点文件里，不需要 `placements.json`。`personas.json` 的 `common` 加上当前命中的条件描述组成 AI 角色人格。另可按需添加 `player/indicators.json` 和 `player/rules.json`，为玩家定义运行时指标与规则。具体写法见 [苏念剧本配置入门](docs/苏念剧本配置入门.md)。

`rules.json` 中当前可直接运行的 `trigger` 为 `semantic`（AI 识别玩家话意）和 `automatic`（有效操作后后端自动检查）；`action` 是预留给后续明确操作入口的类型，不会由聊天提案触发。`when` 是实际生效门槛，`candidateWhen` 控制是否提供给 AI 作为候选。`once`、`priority`、`exclusiveGroup` 控制重复和互斥；`positiveExamples`／`negativeExamples` 帮助 AI 判断语义。规则可更改指标及可见性、物品、地点和图鉴。普通聊天不自动加好感；苏念从线上到饭店、再到家中，是后端把不可逆布尔指标写为真后派生出的结果，不需要玩家点击“切阶段”。

条件支持嵌套的 `all`、`any`、`not`，以及 NPC／玩家指标、玩家表单、NPC 当前地点、时段、带标签道具和事件完成等判断。在 NPC 自己的文件里，`indicator` 可省略 `npcId`；跨 NPC 须写明。物品的发现与获取是两个独立门槛；唯一归属、NPC 位置及指标运行值保存在存档，静态 JSON 不被改写。AI 只得到当前 NPC 的派生人格、状态、相关对话和候选规则摘要，返回角色回复及建议事件 ID；服务器复核条件并原子执行效果。隐藏指标可参与 AI 与规则，但不在玩家资料或游戏日志中显示精确值。

剧本只包含 JSON 和静态资源，不运行自带代码。发布后应保持同一版本内容不变；改动存档相关内容时更新 `version`。存档同时绑定版本和剧本内容哈希；不匹配时拒绝读取，不做旧档迁移。通用开局引导已从界面移除，玩家可自由聊天与探索。

## 检查

```bash
npm test
npm run build
```

游玩存档仍使用游客 Cookie，没有玩家账号、在线遇见其他玩家或跨设备存档同步。创作者账号只管理故事，不自动绑定玩家进度。服务端数据位于 `data/game.sqlite`；浏览器清除游客 Cookie 后，原进度不会自动关联到新的游客身份，因此可通过存档导出和导入备份。
